# Android TV accessibility and quality guidance

**Scope:** native Java Views, Media3/IMA 1.11.1, minSdk 26 / targetSdk 35. Research only; this is not an implementation audit. Android accessibility guidance is not all a TV checklist gate. WCAG is a supplementary benchmark here, not a claim that native Android TV apps must formally conform.

## Priorities and status of guidance

Design for the 10-foot, shared-screen setting: legible information, simple controls, and consistent visible D-pad focus. Google's current TV quality checklist defines Tier 3 (TV Ready: fundamental usability), Tier 2 (TV Optimized), and Tier 1 (TV Differentiated: premium). For Play-distributed TV apps, prioritize Tier 3 checks: landscape without vertical letter/pillarboxing (`TV-LO`), a full, nontransparent display (`TV-TR`), and no important content cut off (`TV-OV`), all functions D-pad navigable (`TV-DP`), no dependency on a remote Menu key (`TV-DM`), and Back eventually returns to TV home (`TV-DB`). The enhanced accessibility package (`TV-AX`) is Tier 1, not Tier 3. Other Android accessibility pages supply recommendations, not additional checklist gates or statements of law.

### D-pad focus, selection, and TalkBack

Every action should work with D-pad directions, center/select, and Back—not only touch, pointer, hover, or an optional remote key. Use native Views' directional focus by default; add `nextFocusUp/Down/Left/Right` only to fix demonstrated bad routes. Keep focus visible, unobscured, and unclipped in rails, pagination, dialogs, authentication, ad breaks, and playback controls. Restore focus to a sensible surviving control after closing a page or overlay; loading/disabled content must not strand users.

Distinguish **focus** (temporary remote target) from **selection** (persistent chosen season, episode, audio/caption track, or other state). Moving focus must not activate playback or change selection. Show focus, selected, playing, and progress states differently; never rely on color alone. At TV distance use a strong outline/surface change plus restrained scale or brightness feedback, and ensure its halo is not clipped. A selected item should remain identifiable after focus moves.

TalkBack traversal is not the same as D-pad focus. Give actionable icon-only Views localized `contentDescription`s; ordinary `TextView` text is spoken automatically, so do not duplicate it with a description. Describe informative images, mark decorative Views `importantForAccessibility="no"`, and associate form labels with `labelFor`. Group related card metadata for screen readers where appropriate without hiding real actions. Custom seek bars need useful role, value/state, and accessible actions; Java `AccessibilityDelegate` and `announceForAccessibility()` help when default Views are insufficient. Announce meaningful changes (caption state, next-episode countdown), not every playback tick.

Follow Android's TV TalkBack evaluation from first launch/sign-in to discovery and playback. Check row headings, titles, control order, labels/states, and whether pausing/resuming causes speech to mask programme audio. Test play/pause, rewind/fast-forward timestamps, audio descriptions when available, audio-language changes, subtitles/captions, and settings with TalkBack on. Preserve official catalog, region, authentication, ads, and DRM gates: accessibility should make the same authorized flows usable, not bypass them.

### Text, contrast, targets, localization, motion, captions

Android TV recommends layouts that grow with text: use `wrap_content`, rearrange components at larger scales, and avoid `sp` text in inflexible components. Android 12+ TV settings support text scaling; the guide demonstrates `adb shell settings put system font_scale 1.2f`. Test default and enlarged scale with long localized titles, metadata, errors, and controls; essential text must not overlap, disappear, or push focus off-screen. Use string resources and inspect `resources.configuration.fontScale` in custom Views rather than fixed-height text boxes.

Android Views accessibility guidance recommends text contrast of **4.5:1** below 18sp (or bold below 14sp), and **3:1** for larger text. Check text over artwork/scrims and the distinction of focus/toggle indicators as well. WCAG's non-text contrast and focus principles are useful supplemental checks, not TV-app certification. Android Views guidance recommends at least **48 x 48 dp** for an interactive focusable/touch area, with larger better. This is a general Android recommendation, not a distinct TV D-pad minimum. WCAG 2.2's **24 x 24 CSS-pixel** target minimum is specifically for pointer inputs, not five-way remote control. Use generous, simple TV controls and spacing, especially for seeking and captions.

Localize labels, status, dialogs, and announcements. Support RTL using Android language resources and `start`/`end` instead of fixed left/right alignment; bidi-format mixed-direction dynamic titles/account text. Mirror only graphics whose meaning is directional. Preserve physical left/right seek semantics and episode chronology. Test an RTL locale, long strings, and mixed-script content.

Motion should support, not replace, focus cues. Use brief transitions; avoid flashing, repeated large zooms, or automatic background video that competes with TalkBack. Test animator scale zero and retain a clear static focus state. WCAG 2.2 SC 2.3.3 (Animation from Interactions, Level AAA) is a supplementary reduced-motion reference, not an Android TV checklist rule. Android TV caption settings let users centrally enable captions and choose locale/style. Read `CaptioningManager` enabled state, preferred locale, font scale, and user style; respond to preference changes rather than impose incompatible styling. Android 13+ adds a system audio-description preference via `AccessibilityManager.isAudioDescriptionRequested()`; runtime-guard it for minSdk 26. Expose available tracks and their state, and don't imply an unavailable track exists.

### Layout safety and app-specific decisions

The current TV layout guide recommends 16:9 design at 960 x 540 dp, 1080p assets, and about a 5% safe margin (approximately 48 dp horizontal / 27 dp vertical at that reference size); it notes modern TVs often no longer overscan. The page is internally inconsistent: a later sentence says 58 dp horizontal and 28 dp vertical. Prefer the stated percentage/formula, inset important UI/focus rings, and validate devices; backgrounds and nonessential artwork may fill the screen. Keep app chrome landscape/full-screen and preserve correct video aspect with the required always-Fit behavior; do not crop controls or captions to imitate a phone layout.

Preserve the product contract: season browsing/pagination, durable Continue/history and next suggestions, remote play/seek/captions, two-stage Back (first hide controls, next exit), manual Next, and content-end autoplay. Make both Back stages predictable; the second press must exit, not trap. Keep manual Next independently focusable. Android's TalkBack evaluation warns that automatic playback (such as detail-page trailers) can disrupt blind/low-vision users and recommends a way to pause or stop it. This is not an Android rule banning all episode-end transitions: preserve the required end autoplay as a deliberate app choice, with an announced/visible countdown and D-pad/TalkBack-accessible cancel action. Do not add picture-mode controls: `TV-PI` picture profiles are Tier 1, not a Tier 3 accessibility requirement, and this app deliberately stays always-Fit with no picture mode. No Compose migration is needed; native View focus, XML accessibility attributes, Java delegates, and Views guidance cover this app.

## Validation and caveats

On an Android TV emulator, use arrows, center, and Back across every rail, season/page, load-more state, dialog, ad control, and player action. Check focus restoration after navigation, errors, and network delay; hide/reopen player controls; seek; toggle captions; exercise manual Next and autoplay cancellation. Repeat with TalkBack enabled if the image provides it, including an initial pass without watching the screen. Accessibility-tree inspection complements but does not replace TalkBack. Test enlarged `font_scale` (1.2 and a larger supported value), caption style/language changes, RTL, long text, actual color contrast over light/dark moving frames, and animator scale zero. These are proposed checks only: **no emulator, device, install, or settings command was run.**

Physical TV/streaming hardware is still needed for real remote mappings/repeat behavior, TalkBack and caption availability, OEM text settings, 720p/1080p/4K scaling, overscan and edge clipping, video latency, and focus legibility at viewing distance. Emulator results cannot fully predict panel processing, remotes, or manufacturer-specific accessibility behavior.
