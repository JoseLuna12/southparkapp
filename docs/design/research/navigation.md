# Android TV navigation and catalog UI research

**Scope:** TV information architecture/layout, seasons and episodes, Continue/Next, focus/Back, async states, Java Views, and a concrete proposal for the specified native Java Views app. I started at the official TV design hub and followed its live Foundations and Layout links. Research only: no project files, emulator, or device were touched.

## Verified guidance and distinctions

- **TV quality baseline:** [TV navigation](https://developer.android.com/training/tv/get-started/navigation) calls for a clear path to focusable controls, consistent visible focus, predictable Back, simple hierarchy, and purposeful horizontal/vertical axes. Android generally moves focus to the nearest view; test that first, then add `nextFocus*` only if needed. The [TV checklist](https://developer.android.com/training/tv/publishing/checklist) says UI must work with a D-pad/controller, be legible at viewing distance, allow overscan, and not require touch. This is TV quality guidance, not a widget mandate.
- **Design recommendations:** [Foundations](https://developer.android.com/design/ui/tv/guides/foundations/design-for-tv) emphasizes content-first layouts, large/brief 10-foot text and distinct D-pad feedback. [Layouts](https://developer.android.com/design/ui/tv/guides/styles/layouts) uses 16:9, a 960×540 MDPI canvas, simple focus paths, and vertical category rows/horizontal content. [Cards](https://developer.android.com/design/ui/tv/guides/components/cards) recommends one subject per card, concise copy, and appropriate image ratios; 16:9 is a natural episode-art starting point.
- **Overscan caveat:** Layouts says modern TVs mostly avoid overscan but still recommends a 5% safe area. Its numbers conflict: 48dp horizontal/27dp vertical in one section and 58dp/28dp in another (27 is rounded to 24 in its formula). Use the principle, not false precision: keep text, controls, subtitles/status and focus outlines within about 5% safe margins (roughly 48dp horizontal, 24–27dp vertical at 960×540), let background art bleed to edges, and test target TVs.
- **Back/player:** TV navigation says Back returns to the previous destination, should not be trapped in a confirmation/infinite loop, and normally needs no on-screen Back button. [Playback controls](https://developer.android.com/training/tv/playback/controls) recommends center to play/pause and reveal controls, left/right to seek, up/down to peek information without pausing. Back #1 hiding a transient overlay is a deliberate app choice; #2 must leave playback for its caller, without an exit gate.
- **Continue/Next and frameworks:** Android TV's system Watch Next row (called “Play Next” on screen) is distinct from an in-app Continue shelf. Keep durable app history/recommendations in-app; if publishing system-row items, follow [Watch Next rules](https://developer.android.com/training/tv/discovery/guidelines-app-developers). The checklist forbids a launcher channel imitating Play Next. Current official catalog/details examples use Compose and Leanback is labeled deprecated; neither requires migrating this Java Views app for a redesign. Treat Compose samples as interaction/layout references, not implementation mandates.

## Screen and focus proposal

1. **Home/catalog:** Keep the current primary navigation (a left rail is a good TV choice; preserve a familiar top nav if present). Keep existing catalog, region and account/auth routes discoverable, not in touch-only overflow. Main area: vertical stack of short-titled horizontal shelves—**Continue watching** when populated, **Up next**/recommendations, then official catalog featured/category rows. Preserve existing region, entitlement/auth, ad and DRM behavior; do not invent destinations. Launch focus goes to the first Continue item or first item in the first populated catalog shelf. Left/right traverses a shelf, up/down switches shelves; left from its first card reaches primary navigation. Use one high-contrast focus style with room for scale/highlight. Artwork or async updates must not steal focus.
2. **Series/season:** Selecting a series opens details: title, brief metadata/description and prominent **Resume/Play**. Add a labeled season selector beside/below those actions: focusable chips for few seasons, TV-sized D-pad menu for many—not a phone spinner/sheet. Below show “Season N · Episodes” in a 16:9 grid. Cards show episode number/title, short duration/progress, not long synopses. Start with three columns at the 960dp canvas for legibility, then tune to TV density/focus enlargement; this is a product choice, not Android rule. Focus goes Resume/Play → season selector → first episode; left/right follows rows, up returns to header. Add explicit focus links only if geometry is ambiguous. On season change keep selector focus and restore a stable episode ID (or first); save parent row/card and scroll before navigation, restore on return.
3. **Pagination/Next:** Keep server pagination. A Java `RecyclerView` grid may append focusable **Load more**, or prefetch near the end while preserving IDs/focus; no phone-style pull-to-refresh. Keep manual **Next episode** reachable in player/end state and preserve content-end autoplay. Show the next title and a clear cancel/stop action. This in-app flow is distinct from system Watch Next.
4. **Player:** Keep full-screen video and always-**Fit**; offer no picture mode/fill/crop choice. Preserve Media3/IMA, ads, DRM/entitlement, captions/audio and current playback behavior. Retain familiar remote semantics where compatible. Back #1 hides controls without changing playback; #2 returns to originating season/details and restores episode focus; later Back returns to catalog. At app root, ordinary Back exits.

## Java Views and async states

- **`GridView`** fits a simple uniform adapter-backed episode grid; mixed cards, headers, inline paging and complex restoration are less convenient. **`ListView`** is vertical/one-dimensional, useful for a simple season list but not a multicolumn episode grid or horizontal shelf. See [GridView](https://developer.android.com/reference/android/widget/GridView) and [ListView](https://developer.android.com/reference/android/widget/ListView); these are API tradeoffs, not TV design rules.
- Prefer AndroidX **`RecyclerView`** in Java for this catalog: horizontal `LinearLayoutManager` shelves in the vertical catalog and a single `GridLayoutManager` for episodes. Use stable content IDs, save/restore focus and scroll across pages/screens, and avoid vertically nested `ListView`/`GridView` competing for scroll/focus. Keep an existing Views implementation if it works. The official Compose [catalog sample](https://developer.android.com/training/tv/playback/compose/browse) `LazyColumn`/`LazyRow` model is transferable; no code port is needed. See [RecyclerView API](https://developer.android.com/reference/androidx/recyclerview/widget/RecyclerView).
- **Loading:** retain screen shell/selection; show non-focusable placeholders and concise status, with a meaningful focus target. Appends must not steal focus. **Empty:** distinguish empty catalog/season from no Continue history or no results; state it briefly and offer relevant actions only. **Error:** keep failure local to shelf/page, expose reachable Retry and preserve focus/scroll; avoid unescapable routine-error modals. Auth/DRM failures use existing routes and preserve the return destination.

## Validation

With D-pad and physical TV, traverse all controls; test all four directions at row edges, season changes, page append, empty/error and returns from player/details. Verify focus never disappears/jumps on refresh; both Back stages and root exit; safe margins, edge-to-edge backgrounds, viewing-distance legibility, localization and 720p/1080p. Exercise signed-in/out, region changes, ads, DRM denial, captions/audio, durable history, manual Next and autoplay without regression. Focus restoration, async behavior and grid count are app decisions requiring validation.
