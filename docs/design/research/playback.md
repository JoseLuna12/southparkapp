# Android TV playback and Media3 guidance (Java Views)

**Scope.** Actionable playback guidance for the current Java Views / Media3 1.11.1 + IMA app, with minSdk 26 / target 35. This is a documentation-only review; no project or device validation was performed. The official TV hub at [developer.android.com/design/ui/tv](https://developer.android.com/design/ui/tv) is reachable, and its real “Foundations guide” link resolves to [Design for TV](https://developer.android.com/design/ui/tv/guides/foundations/design-for-tv). The alternate candidate [design/ui/tv/guides/overview](https://developer.android.com/design/ui/tv/guides/overview) returned HTTP 404 and is not evidence. The [Media3 hub](https://developer.android.com/media/media3) and its linked player/UI/session documentation were read. Treat the platform principles below as recommendations; preserve the app-specific catalog, region, auth, ads, DRM, persistence, and navigation behavior as product constraints.

## Player and transport architecture

Keep the existing View-based playback path; the official Media3 Views guide documents `PlayerView` as an XML `View` that renders video, subtitles, and playback controls, attached with `setPlayer(Player)`. Media3 `Player` is the common contract for playback, position, seeking, playlists, and rendering; `ExoPlayer` is its standard implementation. `PlayerView` also contains `PlayerControlView`; the latter is **not** intended to be used standalone. Start with `PlayerView` and its attributes/setters; when the redesign needs a materially different controller, supply the documented custom controller layout (`@id/exo_controller`) and bind it to the same `Player`, rather than creating a second playback engine. [Views UI](https://developer.android.com/media/media3/ui/playerview) · [Media3 Player](https://developer.android.com/media/media3/session/player)

For a long-form episode, make a small, legible primary transport group: play/pause, elapsed/remaining progress with seeking, and an available Next action. Put caption/audio selection and any secondary settings in a separate, D-pad-reachable panel. Use `Util.shouldShowPlayButton(player)` and `Util.handlePlayPauseButtonAction(player)` for correct Java play/pause behavior after ended or failed playback. Custom controls must listen for `Player.Listener` updates and check supported player commands before enabling an action; Media3 specifically warns generic controls not to call unsupported commands. Do not add a picture-mode selector: keep the existing always-Fit presentation as an explicit app choice, and verify it is unchanged for differing aspect ratios. [UI customization](https://developer.android.com/media/media3/ui/customization) · [PlayerView](https://developer.android.com/reference/androidx/media3/ui/PlayerView) · [PlayerControlView](https://developer.android.com/reference/androidx/media3/ui/PlayerControlView)

**Remote input and Back.** Android TV’s remote is primarily D-pad/select/back; focus and feedback must be obvious at 10 feet. The Media3 TV page gives a concrete Java integration: request `playerView.requestFocus()` and delegate `Activity.dispatchKeyEvent(KeyEvent)` to `playerView.dispatchKeyEvent(event)` before `super`. Preserve a visible D-pad focus path for any custom control/settings overlays; do not assume every remote has dedicated transport keys. The built-in controller default show timeout is 5,000 ms (`PlayerControlView.DEFAULT_SHOW_TIMEOUT_MS`); choose a deliberate timeout and reveal/reset controls on relevant remote activity. The requested **two-stage Back** is an app choice, not a Media3/platform mandate: while controls are visible, first Back hides them; with controls hidden, Back returns to the prior destination. A settings panel should close before playback exits. Android TV guidance favors predictable Back to the previous destination and cautions against confirmation gates/infinite loops; avoid a confirmation dialog or a dead-end. [Media3 Android TV](https://developer.android.com/media/media3/ui/androidtv) · [TV navigation](https://developer.android.com/design/ui/tv/guides/foundations/navigation-on-tv) · [PlayerControlView reference](https://developer.android.com/reference/androidx/media3/ui/PlayerControlView)

## Metadata, captions, ads, and episode progression

Keep series/season/episode identity anchored in the existing catalog model. A `MediaItem` may carry a stable `mediaId`, app `tag`, URI and metadata; map trusted catalog title/artwork to the playback UI and, if used, the `MediaSession` metadata. `MediaMetadata` has general fields such as `title`, `displayTitle`, `subtitle`, and `description`, but `subtitle` means a secondary title—not closed captions—and it does not provide a season/episode-number pair. Keep `SxxEyy`, season membership, region availability, and pagination in the app’s catalog data; refresh the visible title/next suggestion on `onMediaItemTransition` and `onMediaMetadataChanged`, not by inventing values from a stream. [Media items](https://developer.android.com/media/media3/exoplayer/media-items) · [Metadata](https://developer.android.com/media/media3/exoplayer/retrieving-metadata) · [MediaMetadata reference](https://developer.android.com/reference/androidx/media3/common/MediaMetadata)

For caption/audio settings, inspect the tracks when known (`Player.Listener.onTracksChanged`) and update the selected choice through `Player.setTrackSelectionParameters`; persist user choices only through the app’s existing preferences path. Offer “Off” only when appropriate and handle no selectable text/audio track gracefully. Do not conflate title subtitles with text tracks. The TV D-pad should reach and leave the settings panel without losing playback position. [Track selection](https://developer.android.com/media/media3/exoplayer/track-selection)

Treat the existing IMA/ads/DRM path as a protected integration boundary. Media3’s IMA library provides `ImaAdsLoader`; `PlayerView` hides transport controls during ads by default, and IMA-rendered skip/more-info views cannot be visually customized. Avoid placing redesigned overlays over those views; a custom `AdViewProvider` must register app overlays used during ads. Respect ad skip timing, keep Next/content-seek from bypassing an in-progress ad, and gate content start/next through existing auth, region, ad-tag, and DRM-license resolution. Media3 DRM configuration requires the DRM system UUID, with license configuration supplied as appropriate; do not replace existing license requests or turn a license/auth failure into an endless retry. [Ad insertion / IMA UI](https://developer.android.com/media/media3/exoplayer/ad-insertion) · [DRM](https://developer.android.com/media/media3/exoplayer/drm)

Manual Next and end autoplay should be distinct, idempotent app flows. Enable manual Next only when the existing catalog says a valid, authorized next episode exists; perform it immediately on selection. For end autoplay, show an “Up next” card/countdown with a cancel/dismiss action, then resolve and start the next item only when the timer expires (or use a queued playlist if that matches existing ad/entitlement semantics). Do not let an implicitly queued playlist advance before the app’s intended prompt. Use `STATE_ENDED`/player transitions and the current content item identity to trigger once; ignore ad state (`player.isPlayingAd()`) and stale/duplicate callbacks. Save Continue/history through the existing durable path before transition, on meaningful position updates, and on exit; do not replace pagination, history, or Continue semantics with the player’s transient queue. Media3 playlist transitions identify automatic transitions, seeks, repeats, and playlist changes, which can help distinguish cases. [Player events](https://developer.android.com/media/media3/exoplayer/listening-to-player-events) · [Media items/playlists](https://developer.android.com/media/media3/exoplayer/media-items)

## Lifecycle, loading, and failure states

Render UI from player events, not optimistic button taps alone. Media3 defines `STATE_IDLE`, `STATE_BUFFERING`, `STATE_READY`, and `STATE_ENDED`; `isPlaying` requires ready, playWhenReady, and no suppression. Model at minimum: catalog/auth resolving; player preparing; initial buffering; playing; paused; ad; caption/settings panel; end/up-next; recoverable error; terminal/auth/DRM error. Keep the show/title context visible when buffering or failing. A spinner is appropriate while the player cannot immediately play; do not report a paused player as loading. On `onPlayerError`, classify the failure (including HTTP response/cause) and provide a concise Retry/back action. Media3 says a failed/stopped playback can be retried with `ExoPlayer.prepare`; retry only after any app-owned expired-auth/token or license prerequisite is corrected, with bounded retry/backoff to avoid loops. [Player events and errors](https://developer.android.com/media/media3/exoplayer/listening-to-player-events) · [ExoPlayer troubleshooting](https://developer.android.com/media/media3/exoplayer/troubleshooting)

Release the player when no longer needed; ExoPlayer’s getting-started guidance calls out freeing scarce resources such as decoders. Attach/detach the same player/view through the screen lifecycle and restore the app’s persisted episode/position rather than assuming an Activity survives. Media3 strongly recommends considering `MediaSession` for TV and long-form video, allowing external/platform controls and power-management signals; a `MediaSessionService` is specifically for playback intended to continue when the app is not foregrounded, not an automatic requirement for this redesign. If the app currently stops playback on exit, keep that behavior explicit and test it with any session integration. [ExoPlayer getting started](https://developer.android.com/media/media3/exoplayer/hello-world) · [MediaSession control](https://developer.android.com/media/media3/session/control-playback) · [Background playback/service](https://developer.android.com/media/media3/session/background-playback)

## Validation matrix (execute on representative real TV remotes/devices)

| Area | Regression checks |
|---|---|
| Focus/transport | D-pad enters controls from video; focus is visible and never trapped; play/pause, seek, and available Next work; unsupported actions are absent/disabled; hard media keys do not double-trigger. |
| Timeout/Back | Controller hides after configured timeout; remote activity restores it; first Back hides visible controls; second Back exits; Back from captions/settings closes that panel first; no confirmation loop. |
| Playback/ads | Initial and midstream buffering, pause/resume, seek boundaries, ad start/skip/end, IMA overlays, and content resume behave correctly; Next cannot bypass an ad. |
| Episode flow/data | Manual Next starts only an available authorized episode; end countdown is cancelable and fires once; history/Continue survive process/activity recreation and app exit; season browse, pagination, title/artwork, and next suggestion remain correct. |
| Captions/DRM/auth | Multiple languages, captions off/unavailable, persistent selection, expired auth, DRM/license denial, and successful refresh/retry all have clear states and preserve entitlement rules. |
| Lifecycle/errors/display | Offline/HTTP/decoder errors, retry, Home/background, return/resume, and release do not leak or duplicate players; fit remains uncropped/undistorted across source aspect ratios. |

**Limitations / risks.** Official docs do not prescribe this app’s countdown duration, history write cadence, exact control composition, retry policy, auth/region rules, or whether playback continues in background; these are deliberate product decisions to preserve from current behavior. IMA ad overlays cannot be re-skinned. Documentation was read, but no repository/build/device tests were run. The alternate TV overview URL is a confirmed 404; rely on the reachable TV hub and the linked foundations page instead. Resource-name/drawable overrides are explicitly unstable/private; prefer documented setters or a custom `@id/exo_controller` layout.
